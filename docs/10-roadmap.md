# Дорожная карта реализации R2D2

Этапы от прототипа до полноценного ассистента. Каждый этап заканчивается
проверяемым результатом.

## Этап 0. Подготовка (1–2 часа)

- [ ] Установить Python 3.11+, создать venv.
- [ ] Создать `.env` из `.env.example`.
- [ ] Получить ключи: OpenRouter, Yandex Cloud (или оба).
- [ ] Создать Telegram-бота (BotFather) и узнать `chat_id`.
- [ ] Зарегистрировать навык в Яндекс.Диалогах (пустой, приватный).
- [ ] Установить cloudflared.

**Результат:** готовое окружение и ключи.

## Этап 1. Скелет сервера + пустой навык (полдня)

- [ ] FastAPI-приложение: `/health`, `/webhook`.
- [ ] Парсинг запроса Алисы (04-alice-protocol.md).
- [ ] Валидация `skill_id`/`user_id`.
- [ ] Ответы-заглушки: приветствие, «помощь», «что ты умеешь».
- [ ] cloudflared-туннель до сервера.
- [ ] Заполнить Endpoint в консоли Диалогов.
- [ ] Проверить голосом: «Алиса, запусти навык Р2Д2» → слышим приветствие.

**Результат:** навык отвечает голосом со Станции.

## Этап 2. Мозг: LLM + простой диалог (полдня)

- [ ] Провайдеры OpenRouter и YandexGPT (05-llm-provider.md), переключатель в `.env`.
- [ ] System-промпт R2D2 (короткие ответы).
- [ ] История в SQLite (последние ~20 сообщений).
- [ ] Обрезка до 1024 симв. и очистка от markdown.
- [ ] Логи скорости (duration) и аварийный ответ.
- [ ] Тест: «Р2, что такое квантовые точки» → осмысленный короткий ответ.

**Результат:** Алиса отвечает сильным LLM.

## Этап 3. Инструменты: Telegram + базовое управление (1–2 дня)

- [ ] `tg_send` — сообщения в ТГ, `spoken_reply`.
- [ ] `system_status` — батарея/CPU/память/аптайм.
- [ ] `open_app` — словарь приложений.
- [ ] `run_shell` — таймаут, классификация риска, подтверждение
      (`confirm_risky_action`).
- [ ] Реестр инструментов + function calling.
- [ ] Тест голосом:
      - «Р2, отправь в телеграм привет» → сообщение в ТГ, озвучка «Отправил».
      - «Р2, какой заряд у ноутбука» → ответ.
      - «Р2, открой браузер» → открывается.
      - «Р2, удали папку tmp» → R2 переспрашивает «Подтверди?» → «да» → выполнит.

**Результат:** R2 управляет ноутбуком и пишет в ТГ.

## Этап 4. Долгие задачи: arxiv-сводка (1 день)

- [ ] `arxiv_search` + фоновый воркер (ack-then-background, 07-latency-strategy.md).
- [ ] Суммаризация сильной моделью в фоне.
- [ ] Доставка результата в ТГ.
- [ ] Таблица `jobs` в SQLite (статусы, таймауты).
- [ ] Тест: «Р2, отправь сводку статей про LLM с arxiv» → мгновенный ответ
      + сводка в ТГ через ~10–30 с.

**Результат:** работает главный «киллер-фича».

## Этап 5. Закатка: стабильность и безопасность (1 день)

- [ ] Ретраи и fallback провайдера.
- [ ] `dangerous_context` — осторожное поведение.
- [ ] `R2D2_ENABLE_SHELL` выключатель.
- [ ] systemd-юниты (сервер + туннель).
- [ ] Логи и маскирование секретов.
- [ ] Чек-лист из [08-deployment.md](08-deployment.md) и [09-security.md](09-security.md).
- [ ] Тест «выдержки»: навык живёт сутки, Диалоги не отключили.

**Результат:** стабильный личный ассистент 24/7.

## Этап 6. Расширения (по желанию)

- [ ] `web_search` (агрегатор / Tavily / Brave).
- [ ] `media_control` (playerctl/pactl).
- [ ] `screenshot` → в ТГ.
- [ ] Файловые операции в ограниченной директории.
- [ ] Списки задач / напоминания в SQLite.
- [ ] Прогноз погоды.
- [ ] Голосовые команды для умного дома (через Яндекс IoT / MQTT) — отдельный
      навык «умного дома» или расширение.
- [ ] Мини-панель `/admin` с логами и историей.

## Критерии готовности MVP

1. Запуск со Станции: «Алиса, попроси Р2 …».
2. Ответы укладываются в 4,5 с (цель < 3 с от нас).
3. Длинный контент уходит в ТГ, голос — только подтверждение.
4. Рискованные команды требуют подтверждения.
5. Приватный навык, только твой Яндекс-аккаунт.
