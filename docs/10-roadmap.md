проверяемым результатом.

> **Что изменилось.** Этапы 0–3 и 6 выполнены и остаются как есть. Этапы 4 и 5
> **заменены** работой над этапом 11: они описывали путь, по которому пойти не

перед собственным агентом opencode». Ниже — что именно появилось; описание

- [x] **Реестр бэкендов из конфигурации**: `config/backends.json`, два `kind`,
      добавление провайдера — один объект JSON без кода.

      ворота C1 на `model id` при старте.
- [x] **Одна сессия на пользователя** в SQLite (`oc_sessions`) + сборщик
      зависших `busy`-сессий.
- [x] **Два агента** в `config/opencode/r2d2.opencode.json`: `r2d2-voice`
      (инструментов почти нет, всё изменяющее запрещено) и `r2d2-agent`
      (полный набор, всё изменяющее спрашивает разрешение). Оба решают **каждый**

- [x] **Сентинел `[[NEEDS_AGENT]]`** и три независимых guard'а против его

- [x] **Шим `opencode/r2d2_cli/r2d2_do.py`**: инструменты R2D2 доступны агенту

- [x] **Документация обновлена** под фактическую архитектуру.

## Критерии готовности MVP

1. Запуск со Станции: «Алиса, попроси Р2 …».
2. Голосовой путь укладывается в `R2D2_FAST_DEADLINE` (3,2 с), весь ход — в 4,5 с.
3. Длинный контент уходит в ТГ, голос — только подтверждение.
4. Рискованные команды требуют подтверждения — и со стороны R2D2, и со стороны
   opencode.
5. Приватный навык, только твой Яндекс-аккаунт.
6. Один вопрос пользователя — одна сессия opencode, контекст живой между ходами.
7. Бесплатный opencode недоступен — ассистент продолжает отвечать из цепочки.
