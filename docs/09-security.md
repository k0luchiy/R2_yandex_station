# Безопасность R2D2

Сервер будет публично доступен через интернет, а R2 может выполнять команды на
ноутбуке. Поэтому безопасность — критичный раздел.

## Модель угроз

- **Кто-то чужой** найдёт URL навыка и отправит запрос → должен быть отвергнут.
- **Несанкционированное** выполнение команд на ноутбуке.
- **Случайные** деструктивные команды через голос (например «удали всё»).
- **Утечка** данных (вывод команд, логи, ключи).

## 1. Валидация входящих запросов (webhook)

В `POST /webhook` проверяем:

1. `session.skill_id` == `ALICE_SKILL_ID` (наш навык).
2. `session.user.user_id` == `ALICE_USER_ID` (белый список — один пользователь).
3. `version` == `1.0`.

При несовпадении → `403` (или валидный ответ «Не авторизован»). Это защищает
от чужих, даже если URL узнают.

> Примечание: протокол Алисы не подписывает запросы (нет HMAC). Полноценная
> защита — только через whitelist + приватный навык (доступ только тебе).

## 2. Приватный навык

- Тип доступа «Приватный» — навык доступен только владельцу на его устройствах.
- Это первый барьер: чужие пользователи вообще не могут запустить навык.
- Даже в приватном навыке оставляем whitelist (защита от прямых POST).

## 3. Инструменты и shell

### `run_shell`

- **Неинтерактивно**: `asyncio.create_subprocess_shell(..., stdin=DEVNULL)`.
- **Таймаут**: `SHELL_TIMEOUT_SECONDS` (по умолчанию 10) — команда убивается.
- **Без sudo** по умолчанию; sudo/пароли — только если явно сконфигурировано
  (и лучше через подтверждение).
- **Классификация риска** (`core/policies.py`):

```python
SAFE_PREFIXES = {"ls", "pwd", "df", "ps", "cat", "echo", "date", "uptime",
                 "whoami", "free", "git status", "curl -s"}
RISKY_KEYWORDS = {"rm", "mkfs", "shutdown", "sudo", "reboot", "kill", "pkill",
                  "dd", "> /dev", "chmod 777", "chown", "mount", "fdisk"}
```

- **Политика:**
  - Команда из `SAFE_PREFIXES` → выполнить сразу.
  - Содержит `RISKY_KEYWORDS` → **требовать подтверждение** (`confirm_risky_action`).
  - Прочее → по умолчанию выполнить, но записать в лог; при сомнении спросить.
- **Подтверждение — одноразовое**, хранится в памяти сессии, не между сессиями.
- **Вывод** урезается (например 2000 симв.) и не озвучивается целиком.

### Прочие инструменты

- `open_app` — только из фиксированного словаря приложений.
- `tg_send` — только на свой `TELEGRAM_CHAT_ID`; токен из `.env`.
- `arxiv_search` — только внешний HTTP-запрос (без локальных операций).

## 4. Секреты

- Все ключи в `.env` (не в git). `.gitignore` содержит `.env` и `db/`.
- Не логировать ключи и токены; при логировании маскировать.
- `TELEGRAM_BOT_TOKEN` / `OPENROUTER_API_KEY` / `YANDEX_API_KEY` — не попадают
  в ответы Алисы и в ТГ.

## 5. Защита от деструктивных действий через LLM

- System-промпт жёстко запрещает разрушительные действия без подтверждения
  (см. [05-llm-provider.md](05-llm-provider.md), правило 6).
- `dangerous_context` из `request.markup` — если Яндекс пометил запрос как
  опасный, R2D2 должен быть особенно осторожен (требовать подтверждение,
  или отказывать).
- Отдельный **мастер-выключатель**: переменная `R2D2_ENABLE_SHELL=false` —
  отключает `run_shell` целиком.

## 6. Логирование

- Логируем: время, skill_id, user_id (маскированно), команду, инструмент,
  статус, длительность.
- Логи хранятся локально; доступ к `/admin` (если делаем) — по паролю/локали.

## 7. Сеть

- Сервер слушает `0.0.0.0:8080` только потому, что к нему обращается туннель.
  Альтернатива: bind на `127.0.0.1` + туннель указывает на localhost (уже так).
- Firewall: закрыть наружные порты, кроме туннеля (80/443 на cloudflared).
- Cloudflared: если домен свой — включить Cloudflare Access (опционально).

## 8. Резюме чек-листа

- [ ] `.env` в `.gitignore`.
- [ ] `ALICE_SKILL_ID`, `ALICE_USER_ID` заданы и проверяются.
- [ ] Навык приватный.
- [ ] `run_shell` — таймаут, без sudo, классификация риска, подтверждение.
- [ ] `R2D2_ENABLE_SHELL` выключатель.
- [ ] Вывод команд ограничен, не в озвучку целиком.
- [ ] Секреты не логируются.
- [ ] Firewall ограничивает доступ к серверу.
