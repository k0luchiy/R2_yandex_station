# Мозг R2D2: LLM-провайдеры, промпты, function calling

## Выбор провайдера

Делаем абстракцию: один интерфейс, два провайдера, переключение в `.env`
(`LLM_PROVIDER=openrouter|yandexgpt`), плюс запасной провайдер при ошибке.

### OpenRouter

- Один API-ключ → доступ к сотням моделей (Claude, GPT, DeepSeek, Llama, Gemini…).
- Отличная поддержка function calling (OpenAI-совместимый API).
- **Из РФ может потребоваться VPN/прокси.**
- URL: `https://openrouter.ai/api/v1`

Рекомендуемые быстрые модели (голос, латентность важна):

| Модель (slug) | Плюсы | Минусы |
|---|---|---|
| `google/gemini-2.5-flash` | ~$0.3/1M ток., очень быстрая (0.5–1.5с), надёжный function calling | Из РФ нужен доступ |
| `openai/gpt-4o-mini` | Быстрая, надёжная, отличный tool calling | Чуть дороже |
| `inclusionai/ling-3.0-flash:free` | Бесплатная, обычно 1–2с, корректный tool calling | Разброс 1–12с, бывают таймауты |
| `google/gemma-4-26b-a4b-it:free` | Бесплатная, ~2с | Rate-limit, разброс латентности |
| `deepseek/deepseek-chat` | Быстрая, дешёвая, хороший русский | — |

> **Проверено на практике (авг 2026):** бесплатные `:free`-модели на OpenRouter
> нестабильны по задержке (1–12с и дольше) и часто отдают 429/502. Для голосового
> лимита Алисы 4,5с надёжнее платная flash-модель (`gemini-2.5-flash`,
> `gpt-4o-mini`). `nvidia/nemotron-3-ultra-550b-a55b:free` при работе выдаёт
> «сырые рассуждения» на английском — не годится.

### YandexGPT (Yandex Cloud AI Studio / Foundation Models)

- OpenAI-совместимый API: `base_url=https://llm.api.cloud.yandex.net/foundationModels/v1` (и alias).
- Серверы в РФ — **без VPN**, низкая задержка.
- Function calling поддерживается (YandexGPT 5 Pro и Lite).
- `yandexgpt-lite-5` заявлен как «быстрый ответ голосовых ассистентов».
- Дёшево (~0,2–0,5 ₽ / 1K токенов).

| Модель (uri) | Назначение |
|---|---|
| `yandexgpt-lite-5` | Быстрые голосовые ответы (по умолчанию) |
| `yandexgpt-pro-5.1` | Сложные вопросы, сводки (для фоновых задач) |

### Правило выбора

- **Весёлые/быстрые ответы, инструменты** — Lite / быстрая модель.
- **Длинные аналитические задачи** (сводка arxiv) — более сильная модель,
  выполняется в фоне (см. [07-latency-strategy.md](07-latency-strategy.md)).

## Единый интерфейс провайдера

```python
class Provider(ABC):
    @abstractmethod
    async def chat(
        self,
        messages: list[dict],
        tools: list[dict] | None = None,
        *,
        max_tokens: int = 400,
        temperature: float = 0.7,
        timeout: float = 3.0,   # жёсткий таймаут под 4,5 с Алисы
    ) -> Choice: ...
```

- `Choice` содержит: `content`, `tool_calls[]`, `usage`.
- Ретрай: 1 повторная попытка при сетевой ошибке/500.
- Fallback: если основной провайдер упал — пробуем запасной из `.env`
  (`FALLBACK_PROVIDER=...`).

## System-промпт R2D2 (ядро поведения)

```
Ты — R2D2, голосовой ассистент в Яндекс Станции. Твои ответы Алиса ЗАЧИТЫВАЕТ
ВСЛУХ. Правила:

1. Отвечай ОЧЕНЬ КРАТКО: 1–3 коротких предложения, как живой человек.
2. Никогда не используй markdown, смайлики, эмодзи, звёздочки, скобки-кавычки,
   спецсимволы — только обычный текст.
3. Не выводи ссылки, длинные списки и большие числа вслух.
4. Если контент длинный (сводка, отчёт, статья, список) — НЕ зачитывай его.
   Используй инструмент отправки в Telegram и подтверди одной фразой:
   «Отправил в телеграм».
5. Если нужен инструмент — вызови его. В аргументах ОБЯЗАТЕЛЬНО укажи поле
   spoken_reply — короткую фразу, которую пользователь услышит сразу.
6. Если команда рискованная (удаление, изменение системы, выключение) —
   сначала вызови confirm_risky_action и СДЕРЖАННО переспроси в spoken_reply:
   «Подтверди: <действие>?» Делай только после явного «да/подтверждаю».
7. Не выдумывай факты. Если не знаешь — так и скажи.
8. Ты общаешься только по-русски.
```

Пример хорошего ответа на вопрос «что такое квантовые точки»:
> «Это крошечные полупроводниковые частицы размером в несколько нанометров.
> Они светятся разными цветами в зависимости от размера — этим пользуются в
> экранах и медицине.»

Пример плохого (зачитывается вслух):
> «Квантовые точки — нанокристаллы... Далее: https://ru.wikipedia.org/... — слишком длинно, есть ссылка, markdown.»

## Function calling: общая схема

Tools передаются в OpenAI-совместимом формате:

```json
{
  "type": "function",
  "function": {
    "name": "tg_send",
    "description": "Отправить сообщение в личный телеграм пользователя. Для длинного контента и отчётов.",
    "parameters": {
      "type": "object",
      "properties": {
        "text": { "type": "string", "description": "Текст сообщения" },
        "spoken_reply": { "type": "string", "description": "Короткая фраза для озвучки, напр. «Отправил в телеграм»" }
      },
      "required": ["text", "spoken_reply"]
    }
  }
}
```

**Ключевой приём `spoken_reply`:** модель при вызове инструмента сразу пишет
фразу для озвучки. Мы выполняем инструмент и возвращаем эту фразу без второго
раунда LLM — это экономит 1–2 секунды. (Детали в [07-latency-strategy.md](07-latency-strategy.md).)

## Обработка без инструментов

Если `tool_calls` пуст → озвучиваем `content` (с обрезкой до 1024 симв. и
очисткой от markdown).

## Ограничение токенов

- `max_tokens`: 300–400 для голосовых ответов (обычно достаточно 1–3 фраз).
- История: последние ~20 сообщений, длинные реплики ужимаются.

## Измерение скорости

В конфиге включаем логирование: время каждого LLM-вызова и полного обработки
запроса. Целевые бюджеты:

| Этап | Бюджет |
|---|---|
| Распознавание + сеть Алисы | ~1,0–1,5 с (вне нашего контроля) |
| Туннель + наш сервер | ~0,1–0,3 с |
| Вызов LLM | 0,5–1,5 с |
| Исполнение инструмента | 0,05–0,5 с |
| **Итого от нас** | **< 2,5 с** |
