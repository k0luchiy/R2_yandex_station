# Грабли и рецепты

Список ловушек, на которые наступают при разработке навыка Алисы, и готовые решения для
типовых задач. Все утверждения с пометками — из [12-sources.md](12-sources.md).

## Несуществующие поля

Самая большая трата времени при разработке навыка — искать несуществующие поля. Их нет **ни в
документации, ни в коде открытых реализаций**. Проверено сплошным поиском.

| Ищете | На самом деле | Источник путаницы |
|---|---|---|
| `request.utterance` | `request.command` + `request.original_utterance` | документация до 2018 г. |
| `response.suggest` | `response.buttons` с `hide: true` | ранние версии; сторонние обёртки |
| `response.smartResponse` | ничего | красивое имя из другой платформы |
| `response.endOfTurn` | ничего | стриминг-ASR из других SDK |
| `response.markdown`, `is_markdown` | ничего | документация других ассистентов |
| `response.media_state` | `<speaker audio="…">` в `tts` | остаток старого API аудиоплеера |
| `response.photos`, `snippets` | ничего | — |
| `dynamic_image_spec` | ничего | **0 результатов на GitHub вообще** |
| `card.image.url` | загрузка по `image_id` | интуиция «картинка = URL» |
| `response.subtitle`, `blocks` | ничего | — |
| `markup` с `hide`/`hide_selective`/`inline`/`raw` | `request.markup.dangerous_context` | другая платформа; `hide_selective` — **0 результатов на GitHub** |
| `request.features` (массив) | `meta.interfaces` | ранняя схема |
| `session.user_id` (верхний уровень) | `session.application.application_id` | помечен как устаревший |
| `meta.country` | — | есть только `locale` и `timezone` |
| `meta.application_type`, `meta.device`, `screen_max`, `wide_screen` | `meta.interfaces` | см. ниже |
| `nlu.intent` (единственное) | `nlu.intents` — карта | путаница с ранней схемой |
| `nlu.confidence`, `nlu.nlu_version` | ничего | — |
| `final` / `is_final` | — | привычка из других протоколов |
| `userstate`, `json`, `data` в ответе | `session_state`, `user_state_update`, `application_state` | — |
| `ScrollCard`, `SmallCard` | `BigImage`, `ItemsList`, `ImageGallery` | старые типы карточек |
| `Yandex.Nlu.CommonIntent`, `Yandex.Nlu.Passport`, `Weather`, `Music`, `Alice.Skill.Path` | `YANDEX.CONFIRM`, `YANDEX.REJECT`, `YANDEX.HELP`, `YANDEX.REPEAT` | **0 результатов** в документации и на GitHub |

### `application_type` и `screen_max` — подробно

Эти поля упоминаются в обсуждениях так, будто они документированы. Проверено: в документации
Яндекс Диалогов их **нет**, в коде открытых реализаций навыков они **не встречаются**, а
значение `skills_assistant` в GitHub принадлежит несвязанным проектам (например, HR-системам
со смыслом «skills assistant»).

**Что использовать вместо:**

```python
interfaces = body.get("meta", {}).get("interfaces", {})
has_screen = "screen" in interfaces
```

**Чего сделать нельзя:** различить Станцию Лайт 2 и Мини 3 Про. В протоколе нет поля, которое
это описывало бы. В каталоге вся линейка — одна запись `station`.

### Устаревшие типы запросов и директивы

Были в документации до 2022 года, сейчас **отсутствуют**:

| Было | Статус |
|---|---|
| тип запроса `AudioPlayer` | убран из документации |
| тип запроса `Purchase.Confirmation` | убран |
| `directives.audio_player` | убран |
| `directives.start_purchase` | убран |
| `directives.confirm_purchase` | убран |

Осталась одна документированная директива — `start_account_linking`. Наличие прочих
**не гарантировано**: это не документированный контракт.

## Ловушки формата

### Ответ без `end_session` считается неполным

`end_session` обязателен **даже если `false`**. Ответ без него расценивается как не
соответствующий формату, а это закрывает сессию:

> Диалог прекратится автоматически, если навык: Прислал ответ, который не соответствует формату.
> Не успел ответить за 4,5 секунды.

### `version` обязателен

Как и `end_session`. Все SDK жёстко пишут `"1.0"`.

### Лимит 5000 символов — это на весь ответ

Самая частая ошибка при сборке ответа из нескольких полей: каждый лимит по отдельности
выполнен, а сумма превышает 5000. Ошибка выглядит молча — навык «не отвечает».

### `request.payload` объявлен строкой, но описан как объект

В таблице документации тип — `string`, в описании — «JSON-объект». Ориентируйтесь на то, что
на практике это объект.

### Кнопка карточки без `button` всё равно отправляет команду

> Если `button` не задан, будет использовано значение `card.title`.

А `button.text` со значением `""` даёт **пустую** команду.

### `hide` решает, какой тип запроса придёт

Самое неочевидное в протоколе. Нажатие на одну и ту же кнопку может дать
`SimpleUtterance` или `ButtonPressed` в зависимости от `payload`:

| Нажата | `payload` | Тип запроса |
|---|---|---|
| кнопка в бабле | любой | `SimpleUtterance` |
| отдельная кнопка (`hide: true`) | пустой | `SimpleUtterance` |
| отдельная кнопка (`hide: true`) | непустой | `ButtonPressed` |
| элемент карточки | непустой | `ButtonPressed` |

Если навык различает типы запроса — этот маршрут надо знать наизусть.

## Ловушки голоса

### На Station карточки не показываются — но `text` всё равно озвучивается

Формулировка документации, которую стоит запомнить дословно:

> На устройствах, которые поддерживают только голосовое общение с навыком, это будет
> происходить **каждый раз**, когда навык присылает карточку в ответе.

Карточка не «иногда не показывается». Она не показывается **никогда**, а Алиса читает `text`.
Значит, отправка карточки в ответ на голосовой сценарий — это трата лимита в 5000 символов
впустую.

### `command` — не то, что сказал пользователь

Из него убрано имя навыка, убран вокатив «Алиса», **исправлены опечатки**, числа приведены к
цифрам, телефоны отформатированы. Всё это недокументировано, кроме чисел и регистра.

Практический совет: показывать модели `command`, но не утверждать, что это исходная речь.
Если исходный текст нужен для отладки — `original_utterance`, из которого надо самому убрать
имя навыка.

### Пунктуация в `command` может остаться

Документация обещает её удаление и тут же приводит пример с сохранённой запятой. **Не стройте
парсер на предположении, что запятых не будет.**

### Соседние цифры склеиваются

> Запрос 79161234567 1234 … преобразовался в два числа — 79161234570 и 1234.

Не извлекайте длинные числа регуляркой из `command`. Отдайте текст модели целиком.

### Латиница и числа в `tts`

Если `tts` совпадает с `text`, то «R2D2» будет произнесено как «рэ два дэ», а «1024» — как
«тысяча двадцать четыре». Для голосового шлюза к LLM разметка `tts` — не украшение, а
корректность.

### Длинный текст вслух

Документация не советует читать длинные ответы голосом и предлагает заранее отвечать
коротким сообщением, а результат отдавать позже.

## Ловушки активации

### Имя навыка нельзя проверить в консоли

> При тестировании в консоли разработчика навык считается постоянно активированным, поэтому
> проверить работу активационных имен здесь нельзя.

Единственная проверка — обычный разговор с Алисой.

### Название из выдуманного слова не распознаётся 2–3 недели

> Если название навыка содержит выдуманное слово или незнакомый бренд, Алиса может не
> распознать его. Чтобы обучить Алису этому слову, потребуется 2–3 недели (после публикации
> навыка).

Это после публикации. Значит, приватный навык не спасает от этого ожидания.

### Склонение важно, а регистр может ломать

Наблюдение из каталога: у навыка, чьи примеры запросов выглядят как
«Алиса, запусти **НАВЫК** Игра Нубик», есть отдельное предупреждение, что команда
«Алиса, запусти Игру Нубик» перестала работать. Разница — падеж и регистр. Официально это
подтверждается правилом морфологии:

> Голосовой помощник умеет понимать различные морфологические формы одного и того же
> активационного имени, чтобы срабатывать даже при неточных совпадениях.

Практический вывод: добавляйте формы в активационные имена, а не надейтесь на морфологию.

### Два похожих названия запрещены

> Схожим до степени смешения являются обозначения, **не имеющие существенных фонетических
> различий при звуковом воспроизведении**.

Отсюда «веселая компания» / «веселая кампания» в документации.

### Только три дополнительных активационных имени

> Можно задать три дополнительных активационных имени.

Вместе с именем навыка — максимум четыре. Экономьте слоты: одно фонетическое, одно сокращённое.

## Ловушки инфраструктуры

### Адрес в консоли — литеральная строка

Стёрли туннель, перезапустили `cloudflared --url`, получили новый адрес — навык перестал
работать, хотя код не менялся. Это самая частая причина «работал и перестал».

### fullchain, а не просто доверенный

Цепочка должна быть полной. Самоподписанный сертификат отвергается с сообщением
«Endpoint URL: Некорректный SSL-сертификат», и проверка происходит **при сохранении** адреса.

### Повторов не будет

Повторные попытки для вебхуков навыков **не документированы** — в отличие от соседнего
продукта, где они описаны явно. Обработчик обязан быть идемпотентным: повторный вызов не
должен дублировать действие.

### Стриминг не спасает таймаут

Таймер идёт до **полного** получения ответа. Отправка заголовков раньше ничего не выигрывает.

### Ноутбук, который спит, нарушает правила модерации

> На каждые 10 обращений допускается лишь 1 ошибка сервера.

> После публикации навыка Яндекс Диалоги периодически проверяют его работу. Если навык не
> отвечает несколько часов, его отключат.

### Приватный навык — максимум пять человек

Юридически. Не «сколько угодно гостей», а пять работников или подрядчиков на тестирование.

### Отклонение обновления не убирает навык

> Если вы уже опубликовали навык, модерация черновика не влияет на отображение навыка в
> каталоге.

Обновление можно отклонить, и старая версия продолжит работать.

### Повторная модерация может отклонить то, что уже одобрили

Наблюдаемый случай: навык опубликован, разработчик сменил иконку, отправил на повторную
модерацию — отклонили **из-за названия**, которое ранее было принято. Помогло письмо в
поддержку. Модератор переоценивает навык по текущему каталогу, и старые навыки попадают под
новые правила.

## Рецепты

### Минимальный голосовой навык

```python
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

app = FastAPI()

MAX_TEXT = 1024


@app.post("/webhook")
async def webhook(request: Request) -> JSONResponse:
    body = await request.json()
    session = body.get("session", {})
    req = body.get("request", {})

    # Проверка живости платформы — до бизнес-логики.
    if req.get("original_utterance") == "ping":
        return JSONResponse(
            {"response": {"text": "", "end_session": False}, "version": "1.0"}
        )

    # Первый контакт: command пустой, отвечаем приветствием.
    if session.get("new"):
        text = "Привет!"
    else:
        text = f"Вы сказали: {req.get('command') or ''}"

    text = text[: MAX_TEXT - 1].rstrip() + ("…" if len(text) > MAX_TEXT else "")
    return JSONResponse(
        {"response": {"text": text, "tts": text, "end_session": False},
         "version": "1.0"}
    )
```

Что здесь важно и что легко упустить: `ping` обрабатывается **первым**, `session.new` даёт
пустой `command` при первом обращении, `end_session` и `version` присутствуют обязательно,
экран не проверяется — потому что ответ голосовой.

### Проверка «экран или голос»

```python
interfaces = body.get("meta", {}).get("interfaces", {})
if "screen" in interfaces:
    ...  # можно отправить карточку
else:
    ...  # только текст и звук
```

### Разбор нажатия на кнопку

```python
req = body.get("request", {})
if req.get("type") == "ButtonPressed":
    action = (req.get("payload") or {}).get("action")
else:
    action = None  # обычный голосовой ход
```

### Ответ с кнопками (экранные поверхности)

```python
response = {
    "response": {
        "text": "Выберите действие",
        "buttons": [
            {"title": "Открыть", "url": "https://example.com", "hide": False},
            {"title": "Отмена", "payload": {"action": "cancel"}, "hide": True},
        ],
        "end_session": False,
    },
    "version": "1.0",
}
```

`title` — максимум 64 символа, `payload` — максимум 4096 байт, не более 6 кнопок в бабле по
рекомендации Яндекса.

### Разметка произношения

```json
{
  "response": {
    "text": "Готово: 3 статьи про RAG",
    "tts": "Готово. sil <[500]> Три статьи про рэ-эй-жи.",
    "end_session": false
  },
  "version": "1.0"
}
```

### Уложиться в таймаут при долгой работе

Единственный масштабируемый приём — ответить сразу, доделать позже:

```python
# 1. Ответить немедленно, уложившись в бюджет.
return JSONResponse(
    {"response": {"text": "Проверяю, пришлю в Telegram", "end_session": False},
     "version": "1.0"}
)

# 2. Работу выполнить вне хода, результат доставить отдельным каналом.
asyncio.create_task(run_long_job())   # с сохранением ссылки на задачу!
```

⚠️ Строка `asyncio.create_task(...)` без сохранённой ссылки — задокументированный способ
потерять работу: цикл держит только слабую ссылку, задача может быть собрана до запуска.
Событие происходит, пользователю ничего не сообщается, в логах нет следов. **Сохраняйте
ссылку.** В R2D2 это ровно тот случай, который уже был исправлен.

### Проверка «есть ли у меня вообще аудитория»

Юридически приватный навык — максимум пять человек. Публикация в каталоге — это другая
история с модерацией, требованиями к описанию, иконке и проверкой прав бренда.

## Чек-лист «почему навык не работает»

1. Адрес в консоли совпадает с тем, что сейчас отдаёт сервер?
2. Сертификат fullchain, без самоподписанного?
3. Ответ приходит вовремя — замерьте от отправки запроса до получения ответа целиком?
4. `end_session` и `version` присутствуют?
5. Ответ — валидный JSON и меньше 5000 символов?
6. `skill_id` и `user_id` в запросе совпадают с настроенными?
7. Навык опубликован, если он приватный?
8. Активационное имя совпадает с тем, что пользователь говорит, **в правильном падеже**?
9. Не включали ли «Нужно устройство с экраном» для голосового навыка?
