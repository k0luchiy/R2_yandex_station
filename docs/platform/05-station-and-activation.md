# Яндекс Станция и активация навыка

Две вещи, которые определяют поведение навыка под колонкой: **какой поверхностью считается
Станция** и **как пользователь её запускает**.

## Главное: Станция — это поверхность без экрана

Не «устройство с небольшим дисплеем», а именно **поверхность без экрана**. Это официальная
классификация платформы, и она важнее любых характеристик устройства.

Из документации «Где работают навыки»:

| Тип поверхности | Что может навык | Пример устройства |
|---|---|---|
| С экраном | показывать картинки, ссылки, карточки | смартфон, сайт, часы, ТВ |
| **Без экрана** | **общаться только голосом** | **Яндекс Навигатор, Яндекс Станция, Яндекс Авто** |

Ровно так это выглядит в запросе — `interfaces` пустой:

```json
"meta": { "locale": "ru-RU", "interfaces": { } }
```

И из руководства по интерфейсу, прямым текстом:

> Устройства, которые поддерживают только голосовое управление (например, **Яндекс Станция**),
> не смогут отобразить графические элементы.

### Что из этого следует

| Элемент ответа | На Станции |
|---|---|
| `response.text` | **озвучивается всегда** |
| `response.tts` | озвучивается, если заполнен |
| `response.card` | **молча игнорируется** |
| `response.buttons` | **молча игнорируются** |
| изображения, аудио через `<speaker>` | работают — это не графика |

И это **не ошибка, не деградация, а штатный режим**. Формулировка документации:

> На устройствах, которые поддерживают только голосовое общение с навыком, это будет
> происходить каждый раз, когда навык присылает карточку в ответе.

То есть если навык отправляет карточку, Алиса всё равно читает `text`, потому что
`text` — это запасной вариант именно для такого случая.

**Практический вывод для R2D2:** не отправлять карточки и кнопки. Они не покажутся, но
съедают часть лимита в 5000 символов. Голосовой шлюз от этого ничего не выигрывает.

### Как определить, что экрана нет

Единственный документированный способ — **отсутствие** `meta.interfaces.screen`:

```python
has_screen = "screen" in body.get("meta", {}).get("interfaces", {})
```

Других признаков нет: ни `device`, ни `application_type`, ни `screen_max` в протоколе не
существует. Ниже — подробный раздел, почему так.

## Чего нет в протоколе для определения устройства

Эти поля часто упоминаются в обсуждениях, но **в документации Яндекс Диалогов их нет, и в коде
открытых реализаций навыков они не встречаются**:

| Поле | Статус |
|---|---|
| `meta.application_type` | не документировано; в коде навыков не встречается |
| `application_type: "skills_assistant"` | не документировано; в GitHub встречается только в несвязанных проектах |
| `meta.device` (`type`, `id`, `model`, `capabilities`) | не документировано |
| `session.application.application_id` | **существует**, но это не устройство — это устойчивый ключ поверхности |
| `screen_max`, `wide_screen` | не документировано; в коде навыков не встречается |

Проверено сплошным поиском по тексту официальной документации и по GitHub. Значения
`skills_assistant` / `assistant` / `browser` / `talker` — это не схема Алисы; они встречаются
в несвязанных проектах (например, в HR-системах как «skills assistant»).

### Что доступно вместо этого

`session.application.application_id` — устойчивый идентификатор поверхности. Он меняется
при смене устройства или приложения и переживает перезапуск навыка. Это **не** идентификатор
модели: у всей линейки Станций один и тот же.

В каталоге навыков поверхности перечисляются отдельно, и там используется внутренний перечень:
`desktop`, `mobile`, `auto`, `navigator`, `station`, `maps`, `watch`. **Одна запись `station` на
всю линейку**, без разделения по моделям. Навык показывается в каталоге как «Работает с
устройствами: Станция и умные колонки», и это единственное пользовательское упоминание.

**Вывод:** различить Станцию Лайт 2 от Станции Миди 3 Про из навыка нельзя. Ни по одному
документированному полю. Если это требуется — остаётся спрашивать пользователя голосом.

## Устройства линейки

Характеристики взяты из пользовательской документации поддержки, а не из документации для
разработчиков навыков. **Ни один документ для разработчиков не описывает различия между
моделями для навыка.**

| Модель | Экран | Микрофоны | Что важно для навыка |
|---|---|---|---|
| **Станция Лайт 2** | у версии с часами — светодиодный дисплей, 36 сегментов | 2 | у версии без часов дисплея нет вообще |
| Станция Мини 3 | светодиодный дисплей, 32 сегмента | 3 | |
| Станция Мини 3 Про | 32 сегмента + контурная подсветка | 3 | |
| **Станция 2** | нет | 4, распознавание до 7 м | |
| Станция Макс | передний дисплей; **видеовыход** 4K по HDMI | 7 + 1 в пульте | HDMI — это вывод *на телевизор*, а не экран устройства |
| Станция 3 | передний дисплей + подсветка | 3, до 7 м | |
| Станция Миди | передний дисплей | 4, до 7 м | |
| **Станция Дуо Макс** | **настоящий сенсорный 10,5", 1920×1200** | 8 | экран есть, но для навыка это ничего не меняет: см. ниже |
| Станция Стрит | нет | 3 | уличная, IP67, аккумулятор |
| Модуль / ТВ Станция | экран телевизора | микрофон в пульте | отдельная платформа YaOS |

### ⚠️ Дуо Макс — ловушка ожиданий

У Дуо Макс есть настоящий сенсорный экран 1920×1200. Легко ожидать, что навык начнёт
отдавать карточки. **Не начнёт.** В каталоге это всё равно одна запись `station`, а в
протоколе нет поля, которое описывало бы этот экран. Платформа не предоставляет навыку API для
экрана Дуо Макс.

То же самое касается Яндекс Авто и Навигатора — они тоже «без экрана», несмотря на наличие
дисплея в некоторых головных устройствах.

### Светодиодный дисплей — не ваш

Дисплей станции показывает часы, погоду, таймер и «эмоции Алисы». Он **не управляется навыком**.
Публичного API для управления им нет.

Существует недокументированный локальный интерфейс: станция поднимает WebSocket на порту
**1961** в локальной сети, с командами вроде `setVolume`, `playMusic` и внутренним флагом
эксперимента `mordovia_long_listening`. Это **не часть SDK навыка** и не поддерживается: это
локальный протокол конкретной прошивки, доступный только из той же сети. Строить навык на нём
нельзя — Яндекс его не гарантирует и может изменить.

Дополнительно: интеграции вроде Home Assistant обращаются не к навыку, а к внутренним
HTTP-API Яндекса с сессионной cookie. Это тоже не поддерживаемый разработчиками навыков путь.

## Активация навыка

### Фразы запуска

**Просто запустить** навык:

- «запусти навык **[имя]**»
- «запусти чат с **[имя]**»
- «давай поиграем в **[имя]**»
- «сыграем в **[имя]**»

**Запустить с командой:**

- «скажи **[имя]** [команда]»
- «узнай у **[имя]** [команда]»
- «попроси **[имя]** [команда]»
- «спроси у **[имя]** [команда]»

### Что приходит в `request.command`

Всё, кроме активационной фразы:

> Вы получите команду в запросе от пользователя в свойство `request.command`. При активации
> навыка в это свойство попадает **весь текст, кроме активационной фразы**. Если пользователь
> просто скажет «спроси Сбербанк» — свойство `request.command` в запросе будет пустым.

> Если пользователь скажет «Спроси у навыка **Название** сколько времени» — в `command`
> придёт только правая часть: «сколько времени».

При этом `original_utterance` **сохраняет** и имя навыка, и слово «Алиса»:

```json
{
  "command": "сколько времени",
  "original_utterance": "Алиса, попроси у навыка Название сколько времени"
}
```

Если нужен только текст команды — берите `command`. Если для логов нужен исходный запрос —
`original_utterance`.

### Выход из навыка

«Алиса, вернись», «Алиса, хватит», «Стоп», «Закончить», «Выйти».

## Имя навыка и активационные имена

### Жёсткие требования

| Параметр | Правило |
|---|---|
| Имя навыка | **2–5 слов**. Одно слово — только если это уникальный бренд |
| Предлоги, союзы, частицы, междометия | не считаются |
| Словарный запас | русский или английский; латиница — только с транслитерацией |
| **Запрещено** | «Алиса», «Яндекс», «Станция» |
| **Запрещено** | родовые команды: покажи, загрузи, попроси, запуск, включи, открой |
| **Запрещено** | родовые названия категорий, кликбейт, превосходные степени |
| Активационные имена | до **3 дополнительных**, каждое **2–4 слова** |
| Сокращение | минимум 3 буквы, расшифровка обязательна в описании |
| Странная ошибка, написанная в разработке | `nan` |

Формулировка, которая объясняет главную причину ограничений:

> Схожим до степени смешения являются обозначения, **не имеющие существенных фонетических
> различий при звуковом воспроизведении**, а также различающиеся только наличием разных
> предлогов, союзов, междометий (например: «веселая компания»/«веселая кампания»).

Правило появилось из-за голосового ввода: Алиса не должна путать два похожих названия.

### Как сделать имя, которое распознаётся

Это самая практическая часть. Официальный пример прямо показывает приём:

> «Изучаем Python» → добавьте активационные имена «изучаем пайтон» и «изучаем питон».

То есть латинское написание дублируется **фонетическим русским**. На живом каталоге это
выглядит так — у навыка «Тесты на знание C++» опубликованы три примера запросов:

- Запусти навык Тесты на знание C++
- Запусти навык **Тесты си плюс плюс**
- Запусти навык Тесты C++

Дополнительные практические соображения, не из документации, а из опыта разработчиков:

- 2–3 простых слога распознаются лучше длинных;
- anglicisms распознаются плохо: навык-плагиат Spotify назван «Спотик», потому что
  «Спотифай» распознаётся ненадёжно;
- имена с ударной омогографией («все/всё») работают хуже;
- проверять распознавание надо **в обычном разговоре**, а не в тестере консоли.

### Официальная рекомендация по имени в омографии

Документация для разработчиков рекомендует выбирать слова, у которых однозначно
произношение:

> Старайтесь выбирать слова, у которых однозначно произношение, не используйте слова-омогографии,
> не используйте слова, значение которых можно спутать. В этом случае Алиса может не
> распознать активационное имя, даже если оно есть в списке.

### Обучение нового слова

> Если название навыка содержит выдуманное слово или незнакомый бренд, Алиса может не
> распознать его. Чтобы обучить Алису этому слову, потребуется 2–3 недели (после публикации
> навыка).

Практический сценарий: если через три недели после публикации слово так и не распознаётся —
либо переименовывать навык, либо писать в поддержку через форму обратной связи с темой
«Алиса не понимает мой бренд». Разбор недели ответа — примерно 2 недели.

### Проверка в консоли невозможна

Существенное ограничение:

> При тестировании в консоли разработчика навык считается постоянно активированным, поэтому
> проверить работу активационных имен здесь нельзя.

Единственная честная проверка — обычный разговор с Алисой на устройстве, на котором вы
авторизованы.

## Приватный навык работает на Станции

Да, и это один из четырёх ручных шагов развёртывания R2D2.

> **Приватный** — после публикации навык доступен только вам (**на всех поверхностях, где вы
> авторизованы под аккаунтом, которому принадлежит навык**).

Отсюда точная последовательность:

1. Зарегистрировать навык в консоли.
2. Опубликовать его **с типом доступа «Приватный»**. Приватные навыки проходят автомодерацию —
   это занимает минуты.
3. Убедиться, что Станция авторизована под тем же аккаунтом Яндекса, которому принадлежит
   навык.
4. Сказать «Алиса, запусти навык **[имя]**».

Что можно проверить без публикации в каталоге:

> Можно ли протестировать навык голосом до публикации? — Да. Для этого сделайте навык
> приватным. Проверьте его работу на поверхностях, которые вы указали в настройках навыка и на
> которых вы авторизовались. […] **Публиковать навык необязательно.**

Формулировка «после публикации» в определении приватного навыка означает, что кнопку
«Опубликовать» нажать нужно — просто навык не попадёт в каталог.

⚠️ В стороннем руководстве встречается утверждение, что достаточно сохранить **черновик** и
Станция его увидит. Это **противоречит официальной документации**. Ориентируйтесь на
приватный + опубликованный.

### Почему `session.new` важен

Приватный навык, активированный впервые, получает запрос типа `SimpleUtterance` с пустыми
полями. На этом ходу `command` пустой — и навык должен ответить приветствием, а не
растерянно молчать. R2D2 именно так и устроен.

## Станция в тестере консоли

В консоли есть переключатель поверхности:

> **Нет экрана** — имитирует работу устройства без экрана, например **Станции Мини**.

Полезно: можно проверить голосовой сценарий, не спрашивая колонку. Но это проверка
поведения, а не проверка распознавания имени — см. выше.
