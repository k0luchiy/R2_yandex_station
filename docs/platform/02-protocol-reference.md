# Протокол: запрос и ответ

Полный справочник формата, который Яндекс Диалоги шлют на ваш `/webhook` и который ждёт в ответ.
Всё здесь — **официально**, если не указано иное; источники в [12-sources.md](12-sources.md).

## Транспорт

| Требование | Значение | Пометка |
|---|---|---|
| Метод | `POST` на адрес, указанный в консоли | официально |
| Схема | **только HTTPS** | официально |
| Сертификат | **только fullchain**; самоподписанный отклоняется | официально |
| Тело | JSON | официально |
| `Content-Type` | в документации **не упоминается**; все SDK отправляют `application/json` | официально (отсутствие) |
| Таймаут | **4,5 секунды** | официально |
| Повтор попытки | **не документирован**, assume at-most-once | официально (отсутствие) |
| Список IP Яндекса | **не публикуется** → IP-allowlist невозможен | официально (отсутствие) |

Обязательность HTTPS формулируется прямо в настройках публикации:

> **Webhook URL** — адрес обработчика навыка. Обработчик должен работать по HTTPS, протокол
> укажите в адресе `https://example.com/alice-webhook/`.

> ⚠️ Платформа принимает только fullchain-сертификаты. При попытке верифицироваться
> с самоподписанным сертификатом вы получите сообщение
> «Endpoint URL: Некорректный SSL-сертификат».

Консоль проверяет адрес **при сохранении**, а не при публикации, поэтому проблема с
сертификатом видна сразу. Полный практический разбор — [07-hosting-and-webhook.md](07-hosting-and-webhook.md).

## Таймаут: 4,5 секунды

Дословно, из `wait-response`:

> Время ожидания ответа от навыка — 4,5 секунды. Если Диалоги не получат ответ в течение
> этого времени, сессия навыка завершится. Алиса сообщит пользователю, что навык не отвечает.

И — что именно входит в эти 4,5 секунды, из `warehouse/concepts`:

> Время ответа — это время **от начала отправки запроса в навык сервером Алисы до полного
> получения ответа от навыка**. В 4,5 секунды входят:
> - установка сетевого соединения;
> - время доставки запроса до сервера навыка;
> - собственное время работы навыка;
> - время доставки ответа до серверов Алисы.

Четыре слагаемых. Отсюда практический вывод: **стриминг не помогает** — таймер идёт до
*полного* получения ответа, и отправка заголовков раньше ничего не выигрывает. Единственный
способ уложиться — ответить быстро, а работу вынести за пределы голосового хода.

Разные лимиты для разных случаев, их легко перепутать:

| Случай | Лимит | Где |
|---|---|---|
| Обычный навык | **4,5 с** | `wait-response` |
| Навык Умного дома | **3 с** | `smart-home/doc/ru/start` |
| Колбэк OAuth | **5 с** | `warehouse/concepts` |

Для OAuth-колбэка важно отдельное последствие: если Диалоги **дважды подряд** не получат ответ
за 5 секунд, **связка аккаунтов разрывается** и пользователю придётся авторизоваться заново.

## Запрос: верхний уровень

```json
{
  "version": "1.0",
  "meta":      { ... },
  "request":   { ... },
  "session":   { ... },
  "state":     { ... }
}
```

`state` присутствует, только если в консоли включено «Использовать хранилище данных в навыке».

### `meta`

```json
{
  "locale": "ru-RU",
  "timezone": "Europe/Moscow",
  "client_id": "<устарело>",
  "interfaces": { }
}
```

| Поле | Тип | Пометка |
|---|---|---|
| `locale` | строка, ≤ 64 | POSIX-формат |
| `timezone` | строка, ≤ 64 | IANA, алиасы допустимы |
| `client_id` | строка, ≤ 1024 | **устарело**: «Не рекомендуется к использованию» |
| `interfaces` | объект | capability-флаги, см. ниже |

Единственный документированный способ узнать, есть ли у устройства экран, — **отсутствие
`meta.interfaces.screen`**.

```json
"interfaces": {
  "screen": {},           // пользователь видит ответ и может открыть ссылки
  "account_linking": {},  // устройство умеет предлагать связку аккаунтов
  "audio_player": {}      // на устройстве есть аудиоплеер
}
```

Поле `payments` тоже встречается в ответах Алисы, но в текущей документации не описано
(практики, наблюдение в реальном payload, апрель 2024).

**На Яндекс Станции `interfaces` пустой.** Разбор последствий — [05-station-and-activation.md](05-station-and-activation.md).

### `request`

```json
{
  "type": "SimpleUtterance",
  "command": "открой браузер",
  "original_utterance": "Алиса, попроси Р2 открыть браузер",
  "payload": {},
  "nlu": {
    "tokens": ["открой", "браузер"],
    "entities": [],
    "intents": {}
  },
  "markup": {},
  "show_type": ""
}
```

| Поле | Тип | Пометка |
|---|---|---|
| `type` | **обязательное** | `SimpleUtterance`, `ButtonPressed`, `Show.Pull` |
| `command` | строка | нормализованный текст, ≤ 1024 |
| `original_utterance` | строка, ≤ 1024 | полный текст запроса |
| `payload` | объект, ≤ 4096 байт | `ButtonPressed` |
| `nlu` | объект | см. [04-nlu-intents-entities.md](04-nlu-intents-entities.md) |
| `markup` | объект | только `dangerous_context` |
| `show_type` | строка | только для `Show.Pull`, значение `MORNING` |

**`request.utterance` не существует.** Это имя из документации примерно до 2018 года. Современная
пара — `command` (нормализованный) + `original_utterance` (дословный). Что именно делает
нормализация и какие поля она стирает — [06-scripts-and-voice.md](06-scripts-and-voice.md).

#### Что при каком типе запроса

| `request.type` | Когда приходит |
|---|---|
| `SimpleUtterance` | пользователь сказал фразу; нажал кнопку в «бабле» с `hide: false`; нажал отдельную кнопку с `hide: true` и **пустым** `payload`; **первый контакт в сессии** |
| `ButtonPressed` | нажата кнопка с `hide: true` и **непустым** `payload`; либо элемент карточки с непустым `payload` |
| `Show.Pull` | утренний шоу-контент; `show_type: "MORNING"` |

Правило `hide`/`payload` настолько неочевидно, что его стоит держать в голове: **нажатие на
кнопку может дать два разных типа запроса в зависимости от `payload`** — [03-response-surface.md](03-response-surface.md).

При **первом контакте** остальные поля `request` пустые: `command` будет `""`, `nlu` — с пустыми
объектами. Это не ошибка, это норма. R2D2 на этом строит приветствие по `session.new`.

#### Проверка живости

`original_utterance` со значением `"ping"` — это проверочный запрос от самой платформы. Так
платформа убеждается, что навык отвечает. `command` при этом пустой.

### `session`

```json
{
  "session_id": "2eac4854-fce721f3-b845abba-20d60",
  "message_id": 4,
  "skill_id": "<ваш skill_id>",
  "user": {
    "user_id": "<ваш user_id>",
    "access_token": "<токен, если есть связка аккаунтов>"
  },
  "application": {
    "application_id": "<устойчивый идентификатор поверхности>"
  },
  "new": true
}
```

| Поле | Пометка |
|---|---|
| `session_id` | ≤ 64 символа; UUID; **временный** — умирает вместе с сессией |
| `message_id` | ≤ 8 символов; растёт на каждом запросе |
| `skill_id` | ваш навык |
| `user.user_id` | идентификатор **пользователя**; стабильный |
| `user.access_token` | приходит **и** в заголовке `Authorization`, если включена связка аккаунтов |
| `application.application_id` | **устойчивый** ключ поверхности; переживает перезапуск навыка |
| `new` | `true` на первом запросе сессии |
| `user_id` (верхний уровень) | **устарело** — использовать `application.application_id` |

**Какой идентификатор для чего.** Три разных вещи, их путают чаще всего:

- `session.user.user_id` — человек. Один на аккаунт Яндекса. Годится для whitelist «свой
  пользователь».
- `session.application.application_id` — устойчивый ключ поверхности. Годится как ключ памяти
  диалога: он переживает и перезапуск навыка, и смену `session_id`.
- `session.session_id` — рамка одного разговора. **Не годится** как долговременный ключ.

R2D2 использует `application_id` с откатом на `user.user_id` — ровно эта схема.

### `state`

Возвращается, если в консоли включено «Использовать хранилище данных в навыке»:

```json
"state": {
  "session": {},
  "user": {},
  "application": {}
}
```

Каждый блок — не больше **1 КБ**. Подробности в [09-identity-and-access.md](09-identity-and-access.md).

## Ответ: верхний уровень

```json
{
  "response": {
    "text": "Открываю.",
    "tts": "Открываю.",
    "card": {},
    "buttons": [],
    "end_session": false,
    "directives": {},
    "show_item_meta": {}
  },
  "session_state": {},
  "user_state_update": {},
  "application_state": {},
  "analytics": { "events": [] },
  "version": "1.0"
}
```

`response` и `version` — обязательные. Остальное опционально.

**`response.end_session` обязателен** — даже если `false`. Без него ответ считается
неполным.

Полный разбор `response` — [03-response-surface.md](03-response-surface.md).

## Лимиты

Собранные в одну таблицу, потому что главная ошибка — перепутать лимит одного поля с лимитом
всего ответа.

| Что | Лимит | Комментарий |
|---|---|---|
| **Весь ответ** | **5000 символов** | не «на текст», а на всё тело |
| `response.text` | **1024 символа** | обязательное; может быть `""`, если заполнен `tts` |
| `response.tts` | **1024 символа** | теги `<speaker>` в лимит **не входят** |
| `response.end_session` | — | обязательное поле |
| `buttons[].title` | **64 символа** | эмодзи допустимы |
| `buttons[].url` | **1024 байта** | |
| `buttons[].payload` | **4096 байт** | |
| `card` → `BigImage.title` | 128 символов | |
| `BigImage.description` | 1024 символа | |
| `ItemsList` → `header.text` / `footer.text` | 64 символа | обязательны, если присутствует объект |
| `ItemsList` → item `title` | 128 символов | |
| `ItemsList` → item `description` | 256 символов | |
| `ItemsList` → элементов | **1–5** | |
| `ImageGallery` → элементов | **1–7 или 1–10** | ⚠️ противоречие в документации |
| `request.command` | 1024 символа | |
| `request.original_utterance` | 1024 символа | |
| `request.payload` | 4096 байт | |
| `session_state` / `user_state_update` | **1 КБ** каждое | |
| OAuth-токен / refresh-токен | 2048 символа | длина значения |
| `expires_in` | 1 … 4 294 967 296 | целое |
| Загружаемое изображение | **1 КБ – 1 МБ** | квот на аккаунт: 100 МБ |
| Загружаемый звук | **до 5 МБ**, **до 120 с** | квот на аккаунт: 1 ГБ |

### ⚠️ Противоречие в документации по `ImageGallery`

`response.md` говорит «от 1 до 7». `response-card-imagegallery.md` говорит «от 1 до 10» в двух
местах. **Оба числа встречаются в официальной документации.** Возьмите 7 как безопасное значение:
нарушение лимита хуже, чем недобор, а при ответе больше 7 элементов платформа может вести себя
непредсказуемо. Неизвестно, за что именно отклоняют при превышении, — тестируйте на своей
шардированной сборке.

## Модель версий

Документирована единственная версия — `1.0`. Что происходит при несовпадении версии, **не описано**.
Все открытые SDK жёстко пишут `'1.0'`. Практический совет: всегда отвечайте `"version": "1.0"`.

## Что делать при ошибке

Отвечайте **HTTP 200** даже при внутренней ошибке, и отдайте осмысленный текст:

```json
{
  "response": {
    "text": "Что-то пошло не так, попробуйте ещё раз.",
    "end_session": false
  },
  "version": "1.0"
}
```

Причина практическая: 5xx означает, что пользователь услышит безликое системное сообщение
Алисы вместо вашего. Отдельная причина — правила модерации: **допускается не более одной
ошибки сервера на 10 обращений**, а навык, не отвечающий несколько часов, Яндекс отключает.

Диагностика по симптомам — [08-errors-and-debugging.md](08-errors-and-debugging.md).

## Чего в протоколе нет

Чтобы не искать, список полей и возможностей, которых **не существует** в актуальной версии
Яндекс Диалогов. Проверено сплошным поиском по тексту официальной документации и по GitHub:

| Не существует | Чем заменено |
|---|---|
| `request.utterance` | `request.command` + `request.original_utterance` |
| `response.suggest` | `response.buttons` (`hide: true` — «подсказки») |
| `response.smartResponse` | — |
| `response.endOfTurn` | — |
| `response.markdown`, `is_markdown` | — |
| `response.media_state`, `response.audio`, `attachments` | `<speaker audio="…">` внутри `tts` |
| `response.photos`, `response.snippets`, `dynamic_image_spec` | загруженные изображения по `image_id` |
| `response.subtitle`, `response.blocks`, `card.image.url` | загруженные изображения по `image_id` |
| `markup` с `hide` / `hide_selective` / `inline` / `raw` | `request.markup.dangerous_context` |
| `request.features` (массив флагов) | `meta.interfaces` |
| `session.user_id` (верхний уровень) | `session.application.application_id` |
| `meta.country` | — (только `locale` и `timezone`) |
| `meta.application_type`, `meta.device`, `screen_max`, `wide_screen` | `meta.interfaces`, `session.application.application_id` |
| `nlu.intent` (единственное), `nlu.confidence`, `nlu.nlu_version` | `nlu.intents` — карта |
| `final` / `is_final` | — |
| `userstate`, `json`, `data` в ответе | `session_state` / `user_state_update` / `application_state` |
| `ScrollCard`, `SmallCard` | `BigImage`, `ItemsList`, `ImageGallery` |
| Интенты `Yandex.Nlu.*` (`CommonIntent`, `Passport`, `Weather`, `Music`, `Alice.Skill.Path`) | `YANDEX.CONFIRM`, `YANDEX.REJECT`, `YANDEX.HELP`, `YANDEX.REPEAT` |

Полные даты и обоснование по каждой строке — [11-pitfalls-and-recipes.md](11-pitfalls-and-recipes.md).
