# Где живёт сервер навыка

Требования к сети, сертификатам, таймауту и — главное — почему адрес в консоли обязан быть
стабильным. Это самая частая причина того, что навык «работал и перестал».

## Жёсткие требования

| Требование | Правило | Где сформулировано |
|---|---|---|
| Схема | **только HTTPS** | настройки публикации |
| Сертификат | **только fullchain**; самоподписанный отклоняется | настройки публикации |
| Домен | нужен, если сервер ваш | инструкция по своему серверу |
| Порт | **не обязательно 443** | — |
| Redirect | **не документирован** — считайте, что не следуют | — |

### HTTPS

Дословно из настроек публикации:

> **Webhook URL** — адрес обработчика навыка. Обработчик должен работать по HTTPS, протокол
> укажите в адресе `https://example.com/alice-webhook/`.

### Сертификат: только fullchain

Это отдельное требование, а не синоним «доверенный»:

> ⚠️ Платформа принимает только **fullchain-сертификаты**. При попытке верифицироваться
> с самоподписанным сертификатом вы получите сообщение
> «Endpoint URL: Некорректный SSL-сертификат».

Практические следствия:

- цепочка должна быть полной — лист плюс промежуточные сертификаты; только лист не хватит;
- `mkcert`, `selfsigned` и прочие локальные CA **не работают**;
- проверка происходит **при сохранении адреса в консоли**, а не при публикации — проблема
  видна сразу, не в бою.

Тоннели (ngrok, cloudflared, Tailscale Funnel) требование выполняют автоматически: TLS
терминируется на их краю, свою цепочку предъявлять не нужно. Это самый сильный довод в пользу
тоннелей перед «своим» сервером с самоподписанным сертификатом.

## Таймаут: 4,5 секунды на всё

Подробно разобрано в [02-protocol-reference.md](02-protocol-reference.md). Здесь — только
практическая часть.

Четыре слагаемых входят в 4,5 секунды:

```
установка соединения → доставка запроса → ваша работа → доставка ответа
```

Ориентир на разбор: холодное TCP+TLS-рукопожатие до дальнего адреса — 150–400 мс. То есть на
собственную работу остаётся примерно 3,8–4,0 секунды.

**Стриминг не помогает.** Таймер идёт до *полного* получения ответа, поэтому отправка
заголовков раньше ничего не выигрывает. Единственный способ уложиться — ответить быстро, а
работу вынести за пределы голосового хода.

**Повторных попыток нет** — по крайней мере они не документированы. Для сравнения: в соседнем
продукте Yandex Messenger повторные попытки описаны явно, в Диалогах — нет. Отсюда рабочее
правило: **считайте доставку одноразовой и делайте обработчик идемпотентным.**

### Что делать, если не уложились

Документация перечисляет приёмы:

- запустить фоновую музыку через `<speaker audio=…>`;
- сказать «повторите через несколько минут»;
- озвучить прогресс с паузами `sil <[1500]>`;
- дать полезный факт вместо ответа;
- **дать ответ сразу**, а результат довести позже.

Последний приём — единственный, который масштабируется. Алиса не умеет присылать сообщения
позже, поэтому «позже» — это отдельный канал. В R2D2 это Telegram.

## Адрес должен быть стабильным

**Консоль хранит буквальную строку.** Если адрес изменился, навык не работает — и неважно,
переоткрывает ли Яндекс DNS. Строка в консоли просто устарела.

Отсюда главное правило: **быстрый туннель, выдающий новый адрес при каждом запуске, для навыка
не годится.**

| Решение | Адрес стабилен | Свой домен | Примечание |
|---|---|---|---|
| Yandex Cloud Functions (через поле Backend) | ✅ | не нужен | навыки Алисы на Cloud Functions бесплатны и не тарифицируются |
| Yandex Cloud Functions + API Gateway | ✅ | нужен | |
| Свой сервер + домен + Let's Encrypt | ✅ | нужен | бесплатно, но обновление сертификата и аптайм на вас |
| Cloudflare named tunnel | ✅ | нужен | домен должен быть на DNS Cloudflare |
| Tailscale Funnel | ✅ | не нужен | адрес вида `https://<устройство>.<tailnet>.ts.net` |
| ngrok free (статический dev-домен) | ✅ | не нужен | домен выдаётся ngrok, изменить нельзя |
| ngrok free (случайный домен) | ❌ | — | только платные тарифы |
| cloudflared **quick** tunnel | ❌ | — | «The hostname changes each time you create a Quick Tunnel» |
| localtunnel `--subdomain` | ❌ | — | «You may not actually receive this name depending on availability» |
| localhost.run free | ❌ | — | адрес меняется при каждом подключении |
| localhost.run своё имя | ✅ | нужен | платно |

### ngrok — что важно знать на 2026 год

С августа 2023 у каждого аккаунта ngrok есть **бесплатный статический dev-домен**, который
остаётся за вами:

> One of the major complaints users have about ngrok is that the URL changes every time the agent
> restarts. **Every ngrok account now comes with a free dev domain** to alleviate this issue.

Бесплатный план: один домен, до трёх онлайн-точек, 20 000 HTTP-запросов в месяц, 1 ГБ исходящего
трафика, один участник, $5 одноразового кредита.

Предупреждение о «странице-предупреждении» на бесплатном тарифе **навыка не касается**: она
показывается только при обращении браузера к HTML-странице. Алиса шлёт `POST` с JSON, поэтому
её вы не увидите.

Про «ngrok http 443»: это номер **локального** порта, который пробрасывается. На стороне
Яндекса URL остаётся `https://<ваш-домен>/<ваш-путь>` — 443 в команде ничего не меняет в
требованиях платформы.

### Tailscale Funnel

Адрес `https://<устройство>.<tailnet>.ts.net`, бесплатно на всех планах, стабильный, TLS
автоматический. Ограничения, под которые надо проектировать:

- только порты **443, 8443, 10000** — значит, приложение слушает любой локальный порт, а
  публичная точка всегда 443;
- только DNS-имена внутри tailnet-домена — **свой домен не подставить**;
- только TLS;
- пропускная способность не настраивается.

### cloudflared: named против quick

- **quick** — `trycloudflare.com`, адрес меняется каждый запуск, гарантий доступности нет,
  лимит 200 одновременных запросов, Server-Sent Events не поддерживаются. Только для разработки.
- **named** — адрес на **вашем домене**, стабильный навсегда, бесплатно, входящих портов не
  нужно, публичного IP не нужно. Требует, чтобы домен обслуживался DNS Cloudflare.

## Порт

443 **не обязателен**. Официальный пример адреса идёт без порта, и ограничения на порт в
документации нет. На практике сообщество использует `:8889`, `:8123` и другие.

Но практический довод всё же в пользу 443: если адрес без указания порта, любой туннель и любой
балансировщик склеиваются без лишней конфигурации. **Отсутствие требования — не повод
использовать нестандартный порт.**

## Редиректы

**Не документированы.** Ни утверждения, что следуют, ни утверждения, что нет.

Рабочее предположение: **не следуют**, отвечайте `200` на точном настроенном адресе.
Редирект `http→https` или `www→apex` перед вебхуком — реальный риск без покрытия документацией.

## Список IP Яндекса

**Не публикуется.** Искали специально: для платёжных систем (YooKassa), Telegram, 8x8, Branch,
Telnyx, IBM такие списки есть, для вебхуков навыков Диалогов — нет.

Практические следствия:

- IP-allowlist по входящим подключениям **невозможен**;
- безопасность обеспечивается только самим URL (неугадываемый путь, секретный сегмент) и
  проверкой `skill_id`/`user_id` внутри;
- через тоннель IP Яндекса видит оператор тоннеля, а не вы — ещё один довод добавить
  секретный сегмент в путь.

R2D2 закрывает эту часть проверкой `skill_id` и `user_id` в теле запроса; секретный сегмент в
пути у него нет.

## Что делает WAF и стоит ли его ставить

Технически можно: Smart Web Security подключается к API Gateway, к виртуальному хосту ALB или к
домену и даёт L7-защиту, WAF, rate limiting и SmartCaptcha.

Доводы против перед навыком:

1. **Лишний хоп против бюджета в 4,5 с.** В него прямо входит установка соединения.
2. **Капча ломает вебхук.** Правило, вызвавшее SmartCaptcha, не отличит Алису от бота.
3. **Правила меняются без вас.** Обновлённый набор правил начнёт отклонять ваш `POST` без
   изменения кода.
4. **Правило «не более одной ошибки на 10 обращений»** делает каждое ложное отклонение
   дорогим.

**Вывод:** WAF имеет смысл, если вы уже на Yandex Cloud и трафик настоящий. Для сервера дома
за тоннелем — не ставьте; добавьте секретный путь и проверку идентичности вместо этого.

CDN здесь неприменим: вебхук — это `POST` без кеширования, кешировать нечего.

## Где разместить: варианты

| Вариант | Адрес | Своё железо | Свой домен | Деньги | Надёжность |
|---|---|---|---|---|---|
| **Cloud Functions, поле Backend** | сам выдаётся | нет | нет | **бесплатно для навыков Алисы** | ✅ |
| Cloud Functions + API Gateway | свой | нет | нужен | почти бесплатно | ✅ |
| Домашний сервер + домен + Let’s Encrypt | свой | да | нужен | бесплатно | зависит от вас |
| Домашний сервер + Cloudflare named tunnel | свой | да | нужен | бесплатно | ✅ |
| Домашний сервер + Tailscale Funnel | свой | да | не нужен | бесплатно | ✅ |
| Домашний сервер + ngrok free dev-домен | свой | да | не нужен | бесплатно | квоты |
| Домашний сервер + DDNS + Let’s Encrypt | свой | да | нужен | бесплатно | ✅ |
| Compute Cloud VM | свой | нет | нужен | платно | ✅ |

Про Cloud Functions полезно знать: максимальное время выполнения — час вместе с холодным
стартом, а холодный старт **съедает ваш бюджет 4,5 с**. Собственное руководство Яндекса по
навыку на Cloud Functions задаёт `Timeout: 2 s` — то есть ниже бюджета Алисы намеренно.

## Влияние модерации на выбор хостинга

Два официальных правила делают надёжность обязательной:

> На каждые 10 обращений допускается лишь 1 ошибка сервера.

> После публикации навыка Яндекс Диалоги периодически проверяют его работу. Если навык не
> отвечает несколько часов, его отключат.

Ноутбук, который спит ночью, нарушает оба правила. Это самое сильное довод в пользу
облачного размещения — сильнее, чем удобство.

## Диагностика

| Симптом | Что проверить |
|---|---|
| «Некорректный SSL-сертификат» | цепочка не fullchain; самоподписанный сертификат |
| Навык не отвечает, логов нет | адрес изменился; истёк dev-домен; туннель упал |
| Ответ приходит, Алиса молчит | невалидный JSON; нет `end_session`; превышен лимит 5000 |
| Редко, раз в N запросов | холодный старт или подвисание |
| 5xx у себя | не забыть отвечать `200` при внутренней ошибке |

Подробнее — [08-errors-and-debugging.md](08-errors-and-debugging.md).

## Проверка сертификата так, как это делает Яндекс

```bash
curl -v https://ваш-домен/alice-webhook
```

Сертификат должен провериться без предупреждений. Загружать приватный ключ во внешние
сервисы проверки не нужно — в самой документации есть предупреждение об этом.
